# FL.ru RSS Telegram Bot

Telegram-бот отслеживает все новые заказы в категории **«Программирование»** на FL.ru и присылает их в личные сообщения Telegram.

RSS-лента по умолчанию:

```text
https://www.fl.ru/rss/?category=5
```

## Возможности

- проверка RSS через настраиваемый интервал — по умолчанию каждые 2 минуты;
- отправка только новых заказов;
- защита от повторных уведомлений после перезапуска;
- хранение обработанных записей в SQLite;
- безопасный первый запуск: текущая выдача запоминается без массовой рассылки старых заказов;
- аналогичная защита при смене RSS-адреса;
- заголовок, описание, бюджет, дата публикации и кнопка перехода к заказу;
- ручная проверка и управление мониторингом командами Telegram;
- ограничение доступа по Telegram ID;
- запуск через Docker Compose или обычный Python.

## Команды

- `/start` — информация о боте и ваш Telegram ID;
- `/status` — состояние мониторинга, последняя проверка и ошибки;
- `/check` — немедленно проверить RSS;
- `/pause` — приостановить фоновые уведомления;
- `/resume` — возобновить мониторинг.

## Быстрый запуск через Docker

### 1. Создайте Telegram-бота

Откройте `@BotFather`, отправьте `/newbot` и скопируйте полученный токен.

### 2. Настройте переменные окружения

```bash
cp .env.example .env
```

Откройте `.env` и укажите:

```env
BOT_TOKEN=ваш_токен
TELEGRAM_USER_ID=ваш_telegram_id
```

Telegram ID можно сначала оставить пустым. Запустите бота и отправьте ему `/start` — он покажет ваш цифровой ID. Затем впишите его в `.env` и перезапустите контейнер.

### 3. Запустите

```bash
docker compose up -d --build
docker compose logs -f
```

Остановка:

```bash
docker compose down
```

Обновление после изменения кода:

```bash
docker compose up -d --build
```

База хранится в `./data/bot.db`, поэтому история не пропадает при пересборке контейнера.

## Запуск без Docker

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main
```

## Настройки `.env`

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен от BotFather | обязательно |
| `TELEGRAM_USER_ID` | кому отправлять уведомления | обязательно для мониторинга |
| `RSS_URL` | адрес отслеживаемой RSS-ленты | вся категория «Программирование» |
| `CHECK_INTERVAL_SECONDS` | интервал проверки | `120` |
| `DATABASE_PATH` | файл SQLite | `data/bot.db` |
| `TIMEZONE` | часовой пояс сообщений | `Europe/Moscow` |
| `MAX_DESCRIPTION_LENGTH` | максимальная длина описания | `1400` |
| `REQUEST_TIMEOUT_SECONDS` | тайм-аут запроса RSS | `25` |
| `LOG_LEVEL` | уровень логирования | `INFO` |

Минимальный интервал проверки — 30 секунд.

## Поведение первого запуска

После первой успешной проверки бот помечает все текущие элементы RSS как просмотренные. Он не присылает десятки старых публикаций, а начинает уведомлять только о заказах, появившихся после запуска.

При изменении `RSS_URL` текущая выдача новой ленты также один раз запоминается без отправки. После этого бот присылает только новые записи.

## Структура проекта

```text
app/
  config.py      # настройки из .env
  database.py    # SQLite и состояние бота
  feed.py        # загрузка и разбор RSS
  formatter.py   # формат Telegram-сообщения
  handlers.py    # команды бота
  monitor.py     # цикл проверки и отправки
  main.py        # точка запуска

tests/           # тесты разбора RSS и текста
Dockerfile
docker-compose.yml
```

## Безопасность

- файл `.env` исключён из Git;
- токен Telegram не должен попадать в репозиторий;
- доступ к командам и уведомлениям ограничивается значением `TELEGRAM_USER_ID`.
